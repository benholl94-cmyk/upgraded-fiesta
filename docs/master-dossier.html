03 · API Reference

hm-gateway endpoints

Everything is served over plain HTTP by a hand-rolled async TCP handler — no framework dependency.

Method & pathPurpose
GET /health /api/health /gateway/healthLiveness + zero_staked failover status
GET /tasks POST /tasks (+ /api, /gateway aliases)In-memory task registry & dispatch
PUT /storage/{key}Write bytes to local disk under HM_STORAGE_ROOT
GET /storage/{key}Read bytes back, raw — no lossy re-encoding
DELETE /storage/{key}Remove a key; idempotent if already gone
GET /memory POST /memory POST /memory/searchPersistent semantic memory (hm-memory + hm-vector) — offline embeddings, cosine search, survives restarts

POST /tasks additionally dispatches to a matching plugin process (hm-plugins + hm-sdk) when the request's taskType is registered in config/plugins.json, and includes its result under plugin_result — see docs/production-api-contract.md for the stdio JSON protocol.

Small payload
$ curl -X PUT --data-binary 'hello' \ http://localhost:8080/storage/small.txt {"status":"stored","key":"small.txt","bytes":5}
Rejected — over the ceiling
$ curl -X PUT --data-binary @big.bin \ http://localhost:8080/storage/big.bin HTTP/1.1 413 Payload Too Large {"reason":"request exceeds 1048576 byte limit"}
